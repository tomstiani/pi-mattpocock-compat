# Domain Docs

## Layout

Single-context: root `GLOSSARY.md` and `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.
If they do not exist, proceed silently. Domain-modeling creates
them lazily as terms and decisions are resolved.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and tests.
Note genuine vocabulary gaps for domain-modeling.

## Decisions

Explicitly surface proposals that contradict an existing ADR,
identifying the ADR and explaining why it should be reconsidered.
